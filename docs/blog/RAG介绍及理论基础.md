# RAG介绍及核心理论

在人工智能的快速发展中，大模型因其强大的数据处理能力和广泛的应用场景而备受瞩目。然而，随着我们对这些模型的深入使用，它们的一些缺陷和局限性也逐渐显露出来。在今天的课程中，我们将首先探讨这些大模型的局限性。这将为我们理解RAG的重要性和优势奠定基础。通过对比分析，我们将更清楚地看到RAG如何成为解决这些问题的关键技术之一。

##  大模型的缺陷与局限性

### 1. 纯生成式大模型的常见问题

生成式大模型，如GPT、BERT等，在自然语言生成任务中展现出了令人印象深刻的能力。然而，这些模型并非完美，它们在实际应用中暴露出了一系列缺陷和局限性。接下来，我们将深入探讨这些常见问题，并分析它们对模型性能的影响。

#### 生成不准确

- **幻觉效应**

幻觉效应是指生成模型在没有足够的上下文信息时，凭空生成看似合理但实际上没有事实依据的内容。由于模型的生成是基于语言模式而不是事实，因此这种现象尤其常见。例如用户问及“拼多多的CEO是谁”，模型可能会生成一个看似合理但实际上不正确的人，或者是甚至是完全虚构的答案，因为大模型没有访问权威数据源的能力。

#### 依赖于训练数据

生成模型在构建流畅文本方面具有显著优势，但它们生成的内容准确性却是一个值得关注的问题。这些模型主要依赖于训练数据中的语言模式，而非真正的理解能力。因此，在面对需要复杂推理或明确答案的问题时，它们可能会产生误导性的信息。

- **知识更新滞后**

生成式大模型的知识完全依赖于它们的训练数据，而这些数据通常是静态的。这意味着模型的知识库无法随着时间的推移自动更新。因此，模型可能无法提供最新的知识或信息。假设模型的训练数据截止于2021年，那么它将无法回答2022年或之后的新闻事件。比如说当用户询问“2024年巴黎奥运会中国得了多少枚金牌？”时，模型可能无法提供正确答案。

- **知识覆盖面有限**

对于小众领域或长尾问题，模型可能因为缺乏足够的训练数据而无法生成准确的答案。例如，如果用户询问一个关于某个冷门哲学家的学说问题，模型可能无法提供精确的回答。

- **无法实时更新知识库**

生成式大模型无法在用户提出问题后实时访问互联网或更新自身的知识库。它们只能依赖于静态的训练数据生成答案，这限制了它们处理需要实时信息的问题的能力。例如用户询问“今天的天气如何？”或者“当前的股票市场行情如何？”，模型无法提供准确的实时信息，因为它没有访问外部信息源的能力。

### 2. 生成模型在处理长尾问题和知识密集型任务时的挑战

生成模型在处理常见问题时表现较好，但在面对长尾问题和知识密集型任务时，它们的表现往往不尽如人意。

#### 长尾问题
长尾问题指的是那些在训练数据中出现频率较低的问题。对于这些问题，生成模型可能会表现出知识不足或生成错误信息的情况。

例如，在开放领域的问答系统中，用户可能会问一些关于某个冷门音乐家或小众历史事件的问题。由于这些问题在训练数据中出现频率较低，模型可能无法生成准确的答案。

#### 知识密集型任务
知识密集型任务通常需要深入的领域知识和复杂的推理能力。这类任务对生成模型提出了更高的要求，尤其是在需要引用具体事实或进行复杂推理时，生成模型往往表现不佳。

例如，在医学问答系统中，用户可能会问一些关于疾病诊断或治疗方案的问题。由于这些问题需要精确的医学知识和推理，生成模型可能会产生不准确或误导性的答案。

## RAG与微调

> 随着大型语言模型热度的不断升温，越来越多的开发者和企业投身于基于这些大模型的应用程序开发中。然而，面对预训练基座模型未能达到预期的表现时，如何提升应用程序的性能就成为了一个迫在眉睫的问题。我们终将会问自己：为了优化结果，RAG (检索增强生成) 和 Fine-Tuning (微调) 怎么选？接下来我将带着大家一起探讨 RAG 和微调在各个维度之间的微妙差别，发掘它们的适用场景。

### RAG 和 Finetuning 方法介绍

#### 1. RAG 技术

RAG (Retrieval-Augmented Generation, 检索增强生成) 是一种结合了检索和生成能力的 NLP 技术。它首先从一个大型的文档数据库中检索出与输入查询最相关的文档，然后利用这些检索到的文档作为额外的上下文信息，辅助生成模型生成更准确、更丰富的回答。RAG 模型通过这种方式结合了 Retrieval (检索) 的精确性和 Generation (生成) 模型的创造性，旨在改善模型对复杂查询的回答能力，特别是在需要广泛背景知识进行回答的场景中。RAG 使得模型不仅依赖于其内部知识，还能动态地利用外部信息源来增强其回答的准确度和相关性。

![rag1.png](/blog/QQ20241105-161701.png)

#### 2. Fine-Tuning 技术

Fine-Tuning (微调) 是机器学习和 NLP 领域的一个核心概念，指的是在一个已经预训练好的模型基础上进行微调，使其更好地适应特定任务或数据集的过程。这种方法在大语言模型中十分常见，因为它允许开发者利用在大量数据上预训练的模型 (如BERT、GPT等) 的通用知识，通过在特定任务的较小数据集上进行进一步训练，来快速提高模型在这个任务上的性能。通过微调，可以根据我们的数据调整模型的权重，使其更适合我们应用程序的独特需求。

### 抉择方法论

#### 做出合理抉择的重要性

RAG和微调都是增强基于 LLM 应用性能的强大技术，但它们解决优化过程的不同方面，所以做出合理的抉择至关重要。RAG和微调之间的细微差别涵盖了模型架构、数据需求、计算复杂性等方面，忽视这些细节可能会使项目进度和预算脱轨。

方法选择错误可能会导致：

- 在特定任务的场景中，由于模型性能不佳，导致输出结果与理想结果相去甚远。
- 如果使用的技术没有对使用情况进行针对性优化，模型训练和推断的计算成本会大幅增加。
- 如果后续转向不同的技术，需要额外的开发和迭代时间。
- 如果选择过于复杂的适应方法，模型的可解释性会受到影响。
- 由于大小或计算约束，将模型部署到生产环境中存在困难。

#### 灵魂六问

##### 1. 用例需要访问外部数据源吗？

面对一个大模型在判断选择微调还是使用 RAG 时，一个关键考虑因素是应用程序是否需要访问外部数据源。如果答案是肯定的，那么 RAG 可能是更好的选择。

RAG 旨在通过从知识来源检索相关信息，然后生成响应来增强大模型的能力。这使得这种技术非常适用于需要查询数据库、文档或其他结构化和非结构化数据存储库的应用程序。检索器和生成器组件可以优化以利用这些外部来源。

相比之下，虽然可以对大模型进行微调以学习一些外部知识，但这需要一个大型的标记数据集，其中包含来自目标领域的问答对。随着基础数据的变化，这个数据集必须进行更新，这使得它在数据源频繁变化的情况下变得不切实际，微调过程也没有明确地对涉及查询外部知识的检索和推理步骤进行建模。

因此，如果应用程序需要利用外部数据源，使用RAG 技术可能比仅仅通过微调来“内置”所需的知识更有效和可扩展。

##### 2. 需要修改模型的行为、写作风格或领域特定知识吗？

另一个非常重要的考虑因素是需要模型调整其行为、写作风格或为特定领域的应用量身定制回答的程度。微调在使大模型适应特定细微差别、语调或术语方面表现出色，如果希望模型听起来更像金融专业人士，或者以鲁迅风格写作，或者使用特定行业的专用术语进行表达，那么在这些数据基础上进行定制可以实现更好的效果，影响模型行为的能力对于需要与特定风格或领域专业知识保持一致的应用程序至关重要。

RAG 技术虽然在整合外部知识方面很强大，但主要专注于信息检索，并不会根据检索到的信息固有地调整其语言风格或领域特定性。它会从外部数据源中提取相关内容，但可能不会展现出经过精细调整的模型所能提供的定制细微差别或领域专业知识。

因此，如果应用程序需要专业的写作风格或与特定领域的术语和惯例深度契合，微调提供了更直接的实现途径。它通过定制化确保与特定受众或专业领域真正共鸣，确保生成内容的真实感。

##### 3. 对于 “幻觉” 的容忍程度如何？

大模型的一个缺点是在使用过程中产生不可控的 “幻觉”，即编造没有现实基础的事实或细节。在精确性和真实性至关重要的应用场景中，这可能会带来比较严重的问题。

微调可以通过将模型基于特定领域的训练数据来一定程度上减少幻觉。然而，当面对不熟悉的输入时，模型仍可能会制造虚假的回应。需要重新训练以持续减少幻觉回复。

相比之下，RAG 由其特性决定天生更不容易产生幻觉，因为相关回答会基于检索到的依据。检索器在生成器构建答案之前从外部知识源中识别相关事实。这一检索步骤充当事实核查机制，降低了大模型产生虚构内容的可能，生成器会一定程度受限于合成受检索上下文支持的回应。

因此，在面对幻觉限制严格的应用场景中，RAG 系统提供了内置机制来最小化幻觉。

##### 4. 可供使用的标记后训练数据有多少？

在选择 RAG 和微调之间时，还需要考虑手头拥有的领域或任务特定的标记训练数据的数量。

对大模型进行微调时，严重依赖于可用的标记数据的质量和数量。丰富的数据集可以帮助模型深入理解特定领域的内涵、复杂性和独特模式，从而使其能够生成更准确和与上下文相关的响应。然而，如果使用的是有限的数据集，微调可能带来的改进可能是微不足道的。在某些情况下，内容有限的数据集甚至可能导致过拟合，即模型在训练数据上表现良好，但丧失了原本具有的通用能力。

相反，RAG 与训练数据无关，因为利用的是外部知识源来检索相关信息。即使没有大量标记的数据集，RAG 仍然可以通过访问和整合来自外部数据源的见解来展现出色表现。检索和生成的结合确保系统保持了解，即使场景特定的训练数据很少。

在实际中，如果拥有大量从场景获取到的复杂性标记数据，微调可以提供更贴合和精细的模型行为。但在数据有限的情况下，RAG 提供了一个强大的替代方案，通过其检索能力确保应用程序保持数据驱动和上下文语境。

##### 5. 数据是静态的还是动态的？

在选择 RAG 和微调之间时，还有一个需要考虑的基础方面是数据的动态性，数据更新频率如何，模型保持最新状态有多重要？

在特定数据集上微调模型意味着模型的知识范围变成了训练时数据的静态快照。如果数据经常更新、改变或扩展，很快就会使模型过时。为了在这样动态的环境中保持模型的时效性，就需要经常重新训练它，这个过程可能既耗时又资源密集。此外每次迭代都需要详细测试，以确保更新后的模型在不同场景下仍然表现良好，并且没有产生新的偏见或理解上的偏差。

比较而言，RAG 在动态数据环境中具有优势。它的检索机制不断查询外部来源，确保生成响应所使用的信息是最新的。随着外部知识库或数据库的更新，RAG 可以无缝集成这些变化，保持其相关性，而无需频繁重新训练模型。

如果当前正在应对快速发展的数据格局，RAG 提供了一种传统微调很难实现的灵活性。通过始终与最新数据保持连接，RAG 确保生成的响应与当前信息状态保持一致，使其成为动态数据场景的理想选择。

##### 6. 对大模型在应用过程中的可解释性要求如何？

大模型虽然能力强大，但操作方式类似黑匣子，其响应背后的推理决策难以理解。仅着眼于模型内部吸收数据集的信息，很难确定每个响应的确切来源或推理过程。这可能会让开发人员或用户难以信任模型的输出，特别是在理解答案背后的“为什么”至关重要的关键应用中。

另一方面，RAG 系统提供了一定程度的透明度，这种透明度通常不会出现在微调后的模型中。考虑到 RAG 的两步性质 “先检索后生成” ，用户可以窥视这个过程。检索组件允许检查选择哪些外部文档或数据点相关。这提供了一系列有形的证据或参考资料，可以对其进行评估，从而理解构建回应的基础。在需要高度可靠性的应用程序中，或者在需要验证生成内容的准确性时，追溯模型对特定数据源的回答的能力是非常宝贵的。

如果透明度和解释模型响应基础是优先考虑的话，RAG 提供了明显的优势。通过将响应生成分解为不同阶段，并允许洞察其数据检索，RAG 促进了对其输出的更大信任和理解。

#### 抉择总结

|    参考指标    | RAG  | 微调 |
| :------------: | ---- | ---- |
|   外部数据源   | ✅    | ❌    |
|  修改模型行为  | ❌    | ✅    |
|  应对 “幻觉”   | ✅    | ❌    |
| 庞大的训练数据 | ❌    | ✅    |
|   数据偏动态   | ✅    | ❌    |

### 额外补充

- 可扩展性：随着模型应用的深入和需求的演变，可扩展性方面也值得关注。鉴于 RAG 的模块化特性，尤其是在知识库增长的情况下，可能会提供更直接的可扩展性。另一方面，经常微调模型以满足不断扩大的数据集可能会对计算能力提出要求。

- 时效性：如果应用程序要求实时或接近实时的响应反馈，那么就需要考虑不同技术引入的延迟因素。与基于内部知识生成响应的微调相比，会在生成响应之前检索数据的 RAG 可能会导致更多延迟。

- 可集成性：如果企业已经建立了某些基础性设施，无论是数据库、云服务还是用户界面，RAG 或微调与现有组件的兼容性都可能影响选择。

- 可维护性：可维护性角度需要结合应用程序的定位和企业的布局考虑，RAG 可能需要对数据库和检索机制进行维护，而微调则需要持续的训练工作，特别是如果数据或需求发生变化时候。

- 可靠性：虽然 RAG 可以从外部数据来源获取信息，并且可以应对各种问题，但经过高质量微调的大模型在某些领域可能提供更有效的结果。

- 用户友好性：企业需要考虑最终用户及其需求，如果他们需要详细的、有参考支持的答案，RAG 可能更有效；如果他们重视速度和领域专业知识，那么一个经过微调的大模型可能更合适。

- 投入成本：微调可能花销更大，特别是对于大参数的模型而言。但在过去的几个月里，由于 QLoRA 等微调技术的出现，成本已经显著下降。建立 RAG 可能需要较大的初始投资，包括集成、数据库访问，甚至可能还有对外部知识库的定期维护等等。

- 合规性：存储和从外部数据库检索数据可能会引发隐私问题，特别是对于敏感数据。另一方面，一个经过高质量微调的大模型，虽然不会查询实时数据库，但仍可能根据其训练数据产生输出，这可能会引起其自身的道德问题。

#### RAG 与微调的未来

其实 RAG 与微调技术并不是两个对立面，它们既可以独立使用，也可以共同工作，特别是在企业计划塑造独有标签的应用程序的时候。

通过微调可以确保对客交互终端与企业的品牌、常用语及业务知识保持一致，处理大多数典型的客户问答场景。然后，RAG 可以作为一个补充支持，用于更具动态性或特定的查询场景，确保终端可以从最新的企业文件或数据库中获取信息，从而最大程度地减少错误。通过整合这两种方法，企业可以提供全面、及时和品牌一致的客户认可体验。

### 结论

在 RAG 和微调之间抉择需要对特定应用程序的独特需求和优先事项进行谨慎评估，并不存在一种适合所有情况的解决方案，成功之道是将优化方法与任务的具体要求相匹配。需要注意的是避免先入为主的假设和思维定式，像任何其他技术一样，它们的适用性取决于具体的工作，手段和目标的不匹配会阻碍项目进展。通过评估 “灵魂六问” 中的关键标准，组织可以就最佳实践进行决策。在某些情况下，利用 RAG 和微调的混合方法可能是更好的选择。



## 什么是RAG

在深入理解了RAG与微调技术之间的差别之后，我们现在将正式启程，深入探索RAG的精彩世界。

### 基本概念
RAG（Retrieval-Augmented Generation，检索增强生成）是一种创新的模型架构，它巧妙地融合了信息检索和文本生成两大技术。与传统的生成模型不同，RAG在构建答案时，不仅依赖于内部训练数据，还主动从外部知识库中检索相关信息，以此作为补充，生成更高质量的回答。

- **案例分析**：在开放领域问答系统中，RAG模型首先从庞大的知识库中检索与用户问题紧密相关的文档，如维基百科的文章或其他权威资料。然后，模型会综合这些文档中的信息，生成一个既准确又详细的答案。

### 核心思想
RAG的核心思想在于将高效的信息检索与智能的文本生成相结合，以此弥补纯生成式模型的不足。具体而言，RAG模型通过其检索模块，从外部知识库中提取与用户问题相关的文档。这些文档随后被用作生成模型的输入，为其提供丰富的上下文信息，从而辅助生成模型产出更加精确和可靠的答案。

### 优势

RAG技术之所以在众多应用场景中崭露头角，主要归功于其以下几个显著的优势：

1. **深度整合外部知识**：RAG模型不仅局限于内部训练数据，还能高效地整合外部知识库中的丰富信息。这种能力使得RAG能够提供更深入、准确且有价值的答案，极大地提升了生成文本的可靠性和深度。

2. **动态知识更新**：RAG模型配备了先进的检索库更新机制，能够实现知识的即时更新。这意味着无需重新训练模型，RAG就能提供与最新信息同步的回答，保持信息的时效性。

3. **增强答案的可解释性**：由于RAG模型的答案直接引用自检索库中的权威资料，其回复不仅准确，还具有很强的可解释性。用户可以轻松核实答案的准确性，并从信息来源中获得支持，增强了信任度。

4. **灵活定制与适应性**：RAG模型可以根据特定领域的知识库和定制化的提示（prompt）进行调整，快速适应并具备该领域的专业能力。这种高度定制的能力使其在各种垂直领域的应用中都能发挥出色的性能。

5. **降低训练与维护成本**：RAG模型在数据的可拓展性方面表现出色，能够将大量新数据直接更新到知识库中，实现模型知识的持续更新。这一过程避免了重新训练模型的需要，从而降低了训练和维护的成本，提高了经济性。

总而言之，RAG技术以其独特的优势，在提供高质量回答的同时，也为企业和开发者带来了更高的效率和更低的成本。这些优势使得RAG成为了一个在不断变化的信息环境中，能够持续提供价值的强大工具。

### 应用场景

RAG技术以其卓越的检索增强生成能力，在自然语言处理（NLP）的多个领域展现出广泛的应用潜力。以下是RAG技术可以大展身手的一些关键场景：

1. **问答系统（QA Systems）**： RAG技术在构建高效问答系统中扮演着核心角色。它能够处理用户提出的多样化问题，通过检索大规模文档集合来提供精确的答案。这种能力使得问答系统无需针对每个具体问题进行单独训练，极大地提高了系统的灵活性和响应速度。
2. **文档生成和自动摘要（Document Generation and Automatic Summarization）**： RAG技术在自动生成文章段落、文档或自动摘要方面具有显著优势。它能够基于检索到的知识来丰富文本内容，确保生成的内容不仅信息丰富，而且具有高度的相关性和价值。
3. **智能助手和虚拟代理（Intelligent Assistants and Virtual Agents）**： RAG技术可以用于开发智能助手或虚拟代理，这些系统能够结合聊天记录来回答用户的问题、提供信息和执行任务。这种应用减少了对特定任务微调的需求，使得智能助手更加通用和适应性强。
4. **信息检索（Information Retrieval）**： RAG技术能够显著改进信息检索系统的性能，使其能够更准确地理解和响应用户的查询。用户可以提出更具体的查询请求，而系统则不再局限于简单的关键词匹配，而是能够提供更深刻、更个性化的搜索结果。
5. **知识图谱填充（Knowledge Graph Population）**： RAG技术在知识图谱的构建和填充方面也显示出巨大潜力。它可以通过检索文档来识别和添加新的知识点，从而丰富和扩展知识图谱中的实体关系。这不仅提高了知识图谱的覆盖面，也增强了其在各种应用中的实用性。



### 如何通过引入检索机制来弥补大模型的缺陷

为了解决生成模型的上述缺陷，研究人员提出了将“检索机制”与生成模型相结合的方案。检索机制可以从外部知识库中获取最新的、相关的、权威的信息，并将这些信息提供给生成模型，从而提高生成的准确性和可靠性。

#### 检索机制流程

- **用户输入问题**
用户向系统输入一个问题或查询。这个问题可能是一个事实性问题（如“2020年奥斯卡最佳影片是什么？”）或一个需要复杂回答的问题（如“解释相对论的基本原理”）。

- **检索模块工作**
  系统的检索模块会从外部知识库（如维基百科、学术数据库、新闻网站等）中检索与用户问题相关的文档或信息。这些文档可能包括网页、文章、书籍等。

- **生成模型生成答案**

  生成模型接收检索模块找到的相关文档，并将这些文档作为参考输入，生成最终的答案。由于生成模型可以参考检索到的权威信息，因此生成的答案更加准确。


#### 什么是信息检索？

**信息检索**（Information Retrieval，简称IR）是指从庞大的信息集合中找到满足用户查询需求的有用信息。在Internet搜索引擎、电子图书馆或者邮件系统中，信息检索机制都会被用来定位和获取相关信息。

**核心目标** : 找到与用户查询（也称关键词或查询字符串）最相关的结果，并按照一定顺序展示给用户。

#### 传统检索的基础架构

传统信息检索系统主要包括以下几个核心阶段：

1. **文档收集：爬取和存储（Crawling and Storing）**

   首先，要检索的信息需要被系统**爬取和收集**。在互联网搜索场景下，这通常由**网络爬虫（Web Crawlers）**完成。爬虫自动在网页之间跳转，将网页内容抓取下来。同时，这些内容会存储在数据库或文档库中，以供后续检索。

   值得注意的是，文档不一定是HTML网页，它们可以是任何形式的描述性数据，比如PDF文件、文本、图像等。

2. **内容处理（Document Processing）**

   一旦文档被爬取，接下来是对原始数据进行处理。这包括：

   - **去噪处理**：去掉HTML标签、广告、脚本等无关信息，保留正文内容。
   - **分词**：把文本内容拆分成一个个的称为“词”（term）的最小检索单元。在中文中，往往需要使用自然语言处理（NLP）技术进行分词；而在英文中，单词之间通常存在空格分割，因此分词相对容易。
   - **去停用词**：某些常见词（例如, "the", "is", "and"之类的词在英文中，或中文中的"的"、"你"等）被认为不具备检索价值，通常会被去除。
   - **词干提取（Stemming）**：将词变形还原成词根，例如"running"还原为"run"。

3. **索引构建（Indexing）**

   一旦文档内容进行了处理，下一个步骤就是为它们**构建索引**，这也是信息检索系统的核心步骤。

   索引是为了提升查询效率而创建的数据结构，最常见的一种索引结构是**倒排索引（Inverted Index）**。倒排索引的基本思想是：

   - 对每个词项（term）建立一个索引，记录该词项出现在哪些文档中。
   - 例如，针对词项"machine"，系统会建立一个表，保存所有包含"machine"的文档ID或路径。

   这样，当用户查询某个关键词时，系统只需查找索引表，而不需要逐一检查每个文档，显著提高了检索速度。

   **倒排索引示例：**

   ```
   Term        | Document IDs
   ------------|-------------------
   machine     | D1, D3, D5, D10
   learning    | D2, D3, D6, D10
   AI          | D1, D7, D8
   ```

4. **查询处理（Query Processing）**

   当用户提交查询后，系统需要对查询字符串进行处理，用以匹配索引中的内容。查询处理类似于文档处理，也包括以下步骤：

   - 查询解释：包括分词、去停用词等处理。
   - Bool查询：对于简单的关键词查询系统会首先做布尔查询（Boolean Query）。比如用户输入"machine learning"，可以解释为"machine" AND "learning"，也就是两个词都要同时出现在文档中，这样过筛会减少不符合条件的文档。

5. **文档匹配和排名（Document Matching and Ranking）**

   在查询处理完成后，系统会通过倒排索引快速定位包含用户查询关键词的文档列表。但是，由于这些文档的相关性高低不同（即它们与用户查询的匹配程度不同），系统还需要进行**文档评分与排名**。

   **文档匹配模型**有很多，比较经典的方法包括：

   - **布尔模型**：根据关键词完全匹配或者不匹配进行检索，但这种模型在实际应用中过于僵化，没有考虑到文档的相关性。
   - **向量空间模型（VSM：Vector Space Model）**：这是一个更先进的模型。它通过将文档和查询向量化，然后使用**TF-IDF**等度量方法计算相似度。文档的不同词项可以被视为高维空间中的向量，查询也可以投影到这个空间中，两个向量之间的夹角越小，其相关性越大。

    **TF-IDF（Term Frequency – Inverse Document Frequency）**是一个非常经典的评分机制：它对经常出现的常见词赋低权重，而对那些在少数文档中频繁出现的关键词赋高权重。

    **TF（词频）**：某一词语在一个文档中的频率。它度量一个词在某个文档中的重要性。

    **IDF（逆文档频率）**：某一词语在整个文档集合中出现的罕见程度。频繁出现的词会降低其权重。

6. **返回和展示结果（Displaying Results）**

   最后，系统会将根据相关性排序后的列表返回给用户。在搜索引擎应用中，除了显示文档的标题、摘要和URL外，系统还会展示文档内部与查询词相关联的片段（**片段提取**），让用户能更快地判断该文档是否能够满足需求。
   

## RAG的工作流程

### 1. 用户输入问题或查询

RAG工作流程的起点是用户的输入。用户可以输入一个自然语言的问题或查询，这可以是任何形式的文本，比如一个简单的疑问句、一个复杂的查询请求，或者是需要详细信息的特定主题。用户输入的问题是RAG系统需要解决的核心任务，系统将根据这个问题来检索相关信息，并最终生成一个准确的回答。

### 2. 检索模块从知识库中找到相关文档

一旦用户的问题被输入，RAG的检索模块便开始工作。这个模块的主要任务是从预先构建的知识库中检索与用户问题相关的文档。知识库可能包含大量的结构化和非结构化数据，如维基百科条目、新闻文章、学术论文、专业数据库等。检索模块使用高级的搜索算法和自然语言处理技术，如向量搜索、语义匹配和机器学习模型，来识别和提取与用户问题最相关的文档或信息片段。

- **检索策略**：检索模块可能采用多种策略来优化检索结果，包括但不限于布尔检索、概率检索和基于深度学习的语义检索。
- **文档预处理**：在检索到文档后，可能需要进行预处理，如去除噪声、提取关键信息、文档结构化等，以便生成模块能够更有效地利用这些信息。
- **相关性评估**：检索模块还需要评估检索到的文档与用户问题的相关性，以确保生成模块能够接收到最相关的信息。

### 3. 生成模块根据检索结果生成输出

在检索模块提供了相关文档后，生成模块接管工作。这个模块的任务是利用检索到的信息来生成一个准确、连贯且信息丰富的回答。

- **信息融合**：生成模块需要将检索到的多个文档中的信息进行整合，以构建一个全面的回答。这可能涉及到信息的合并、冲突解决和信息的优先级排序。
- **文本生成**：生成模块使用自然语言生成技术，如基于Transformer的模型，来构建回答。这个过程可能包括生成一个概要、草拟回答的初稿，以及细化和优化回答的语言和内容。
- **上下文理解**：生成模块还需要理解用户问题的上下文，以确保生成的回答不仅准确，而且与用户的意图和期望相匹配。
- **反馈循环**：在某些情况下，生成模块可能会生成一个初步回答，然后再次使用检索模块来查找更多信息，以进一步细化和完善回答。

RAG的工作流程是一个动态的、迭代的过程，它结合了检索的广度和生成的深度，以提供高质量的回答。通过这种检索增强生成的方法，RAG能够处理复杂的查询，提供最新的信息，并在各种应用场景中展现出其强大的能力。

## RAG的详细工作流程

<img src="image/图片6.png" alt="RAG流程" style="zoom:50%;" />

### 1. 文档解析

文档解析是RAG工作流程的第一步，它涉及将原始文档（如文本文件、PDF、网页等）转换为机器可读和可处理的格式。

#### 文档格式

在RAG工作流程中，文档解析与拆分是处理多种格式文档的第一步。常见的文档格式包括：

- **PDF**：便携式文档格式，广泛用于文档分享。
- **DOC**：Word文档，微软的办公软件格式。
- **TXT**：纯文本文件，最简单的文档格式。
- **Markdown**：一种轻量级的标记语言，用于格式化文本。
- **HTML**：超文本标记语言，用于创建网页。
- **音频**：声音文件，如MP3、WAV等。
- **视频**：动态影像文件，如MP4、AVI等。
- **QA问答**：问题和答案对，常用于知识库。

#### 文档解析步骤

- **文本提取**：从原始文档中提取纯文本内容，去除无关的格式信息，如页眉、页脚、图片等。
- **预处理**：对提取的文本进行预处理，包括分词、去除停用词、词干提取或词形还原等，以提高后续处理的效率和准确性。
- **结构化**：如果文档包含结构化信息（如标题、段落、列表等），则进行结构化处理，以便于后续的检索和分析。

### 2. 文档拆分

文档拆分是将解析后的文档进一步细分为更小的单元，如句子或段落，以便于后续的向量化和检索。

#### 目的

- **提高检索效率**：通过拆分文档，可以减少每次检索需要处理的数据量，提高检索速度。
- **增强检索精度**：拆分后的文档单元更小，可以更精确地匹配用户的问题。

#### 拆分时可能遇到的问题

- **上下文丢失**：拆分文档时可能会破坏原有的上下文关系，导致信息不完整。
- **信息重复**：拆分可能导致相同信息的重复，影响检索效率。
- **相关性降低**：拆分后的文档片段可能与原始查询的相关性降低。
- **生成质量下降**：拆分可能会影响最终生成回答的质量，因为关键信息可能被分散。

### 3. 文档向量化

文档向量化是将文本数据转换为数值向量，以便机器可以进行计算和比较。

#### 实现过程

- **特征提取**：使用NLP技术（如TF-IDF、Word2Vec、BERT等）从文本中提取特征。
- **向量表示**：将提取的特征转换为固定长度的数值向量，每个向量代表一个文档或文档片段。
- **向量持久化存储**：将生成的向量存储在数据库或内存中，以便于后续的检索。

> 解析和拆分后的文档需要存储在适当的数据库中，以便于检索和进一步处理。常见的数据库类型包括：
>
> - **向量存储库**：用于存储文档向量，以便进行高效的相似度搜索。
>   - 向量数据库用于存储和管理这些数值向量，常见的向量数据库包括：
>     - **Faiss**：Facebook AI Similarity Search，一个用于高效相似性搜索和密集向量聚类的库。
>     - **Chroma**：一个AI原生开源向量数据库，它通过为大型语言模型（LLM）提供知识、事实和技能，使构建LLM应用程序变得容易。 ChromaDB的核心目标是帮助开发者轻松管理和使用高维嵌入向量，特别是与生成式AI（如GPT系列）集成。
> - **搜索引擎**：如Elasticsearch，用于处理大规模文本数据的检索。
> - **图数据库**：如Neo4j，用于存储和查询复杂的关系数据。

### 4. 向量检索

向量检索是使用向量相似度算法（如余弦相似度、欧氏距离等）在向量空间中找到与用户问题最相关的文档向量。

#### 实现过程

- **查询向量化**：将用户的问题转换为与文档向量相同的向量表示。
- **相似度计算**：计算查询向量与数据库中所有文档向量的相似度。
- **结果排序**：根据相似度分数对检索结果进行排序，选择最相关的文档。

### 5. 装载prompt

装载prompt是将检索到的文档和用户的问题一起作为输入，传递给生成模块。这个过程包括：

- **上下文构建**：构建一个包含用户问题和相关文档的上下文，为生成模块提供必要的信息。
- **模板设计**：设计prompt模板，以指导生成模块生成符合要求的回答。

### 6. 调用LLM

调用LLM（Large Language Model，大型语言模型）是使用预训练的大型语言模型来生成回答。这个过程包括：

- **模型选择**：选择合适的大型语言模型，如GPT、BERT等。
- **输入处理**：将装载的prompt输入到语言模型中。
- **回答生成**：语言模型根据输入生成回答，并输出到用户。

### GraphRAG

#### 什么是GraphRAG

GraphRAG 是一种用于增强问答系统的技术，它结合了图数据库与检索增强生成（RAG，Retrieval-Augmented Generation）模型的优点。

- 官网地址：[GraphRAG CLI](https://microsoft.github.io/graphrag/cli/)

RAG 模型通常通过从大型文本数据库中检索相关信息来增强生成式 AI 的回答准确性。通过将图数据库引入其中，GraphRAG 可以更好地处理复杂的知识结构和关系，从而产生更准确、更相关的答案。

在 GraphRAG 架构中，知识图谱（通常存储在图数据库中）被用作信息的补充来源。知识图谱能够高效地表示实体及其间的关系，可以用来更好地理解和生成回答，尤其是在需要理解实体关系和上下文的情况下。此外，结合图数据库的结构化特性，GraphRAG 可以帮助问答系统在复杂查询中提供更精准和详细的应答。

这些系统在技术实现方面涉及以下要点：

1. **信息检索：** 使用自然语言处理技术从图数据库和文本文档中获取相关信息。
2. **上下文增强：** 通过结合结构化和非结构化数据，利用图数据库中的关系和实体信息来增强文本生成。
3. **生成回答：** 在补足的上下文基础上，利用生成模型产生最终的答案。

GraphRAG 技术非常适合于需要深入理解和处理复杂信息领域的应用场景，比如商业智能、医疗诊断、法律咨询等。

#### 相比较RAG的优势

GraphRAG 相较于传统的 RAG（Retrieval-Augmented Generation）具有以下几个优势：

1. **关系推理能力增强** ：由于引入了图数据库，GraphRAG 可以利用知识图谱中预定义的实体和关系，帮助系统更好地理解和推理复杂关系。这对于需要理解不同实体之间关系的问题特别有用。
2. **信息的结构化表示** ：图数据库能够以结构化的方式呈现数据，这使得对于某些查询，系统可以更高效地检索和利用信息，而不是仅依赖于非结构化文本检索。
3. **上下文丰富性提升** ：通过结合文本和知识图谱的信息，GraphRAG 可以提供更加全面和上下文丰富的答案。这种整合有助于更全面地捕捉用户查询所需的信息。
4. **更加灵活的查询能力** ：借助图数据库的灵活查询机制，GraphRAG 能够处理更加复杂的查询需求，尤其是需要多个实体或关系参与推理的问题。
5. **精确性和可靠性提高** ：由于知识图谱提供了经过验证的结构化信息，GraphRAG 的回答不仅建立在检索来源上，还被额外的知识图谱所验证，这增加了回答的精确性和合理性。

通过这些优势，GraphRAG 在需要处理复杂知识结构的任务中，能够比传统 RAG 提供更强大的信息处理能力和更高质量的答案生成。

### RAGFlow

RAGFlow是一个基于深度文档理解构建的开源RAG（Retrieval-Augmented Generation）引擎，它能够结合大语言模型（LLM）为用户提供可靠的问答能力和有理有据的引用。

- 官网：[ragflow.io](https://ragflow.io/docs/dev/)
- GitHub：[github.com/infiniflow/ragflow](https://github.com/infiniflow/ragflow)

![](/blog/QQ20241106-110817.png)

### 核心功能

1. **深度文档理解**：RAGFlow强调“Quality in, quality out”，意味着它基于深度文档理解，能够从各类复杂格式的非结构化数据中提取有价值的信息。能够实现真正在无限上下文（token）的场景下快速完成大海捞针测试

2. **兼容各类异构数据源**：RAGFlow支持多种文件类型，包括Word文档、PPT、Excel表格、txt文件、图片、PDF、影印件、复印件、结构化数据和网页等。

3. **自动化RAG工作流**：RAGFlow提供全面优化的RAG工作流，通过提供易用的 API，支持从个人应用到超大型企业的各类生态系统。同时支持大语言模型LLM以及向量模型的配置，以及基于多路召回和融合重排序的高级功能，以提高问答的准确性和效率。

4. **可视化和人工干预**：在文本分块和处理过程中，RAGFlow提供了强大的可视化功能，允许用户手动调整分块结果，确保最终输出的准确性和可靠性。这种灵活性为用户提供了对处理结果的精细控制，以满足特定的业务需求。

5. **有理有据**：它提供关键引用的快照，并支持追根溯源，最大程度地减少幻觉（hallucination）现象，增强了答案的可信度和透明度。

## 总结

在本次课程中，我们深入探讨了RAG（Retrieval-Augmented Generation，检索增强生成）的基本概念、核心思想、优势以及在不同应用场景中的潜力。通过对比分析，我们了解了RAG如何弥补传统纯生成式大模型的缺陷和局限性，特别是在处理需要广泛背景知识、实时数据和长尾问题的场景中。

RAG作为一种创新的技术，通过结合检索和生成，提供了一种强大的方法来处理复杂的查询和提供最新的信息。它的优势在于能够整合外部知识、动态更新知识库、增强答案的可解释性，并具有高度的定制能力和较低的训练成本。随着技术的不断发展，RAG有望在未来的自然语言处理任务中发挥更加关键的作用，为各种应用场景提供更加丰富和准确的回答。
